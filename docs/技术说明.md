# 技术说明（给后续维护 / 排错用）

## 1. 挂点清单

| 目标 | 类 / 方法 | 目的 |
|---|---|---|
| 锁屏时钟容器（主目标） | `com.android.systemui.shared.clocks.AnimatableClockViewWithDate` 自身声明的刷新类方法（`update* / refresh* / setText* / setTime* / setDate* / apply* / onTime* / onDate* / onConfig* / format* / setColor* / init*`）+ `onAttachedToWindow` / `onFinishInflate` / `onConfigurationChanged` / `onWindowVisibilityChanged` | 一旦出现或刷新，立刻执行隐藏策略 |
| 框架生命周期兜底 | `android.view.View#onAttachedToWindow`、`View#onVisibilityChanged(View,int)`、`View#onWindowVisibilityChanged(int)`（全局各挂一次，回调内按目标类过滤） | 锁屏一出现就生效，不必等分钟跳变 |
| 其它候选类 | `...shared.clocks.AnimatableClockView`、`...clocks.AnimatableClockView`、`com.android.keyguard.KeyguardClockSwitch`、`...statusbar.phone.KeyguardClockSwitch`、`...statusbar.phone.KeyguardStatusView` | AOSP / 其它 ZUI 版本的兜底 |
| 自动发现 | 由 `TargetScanner` 从 SystemUI dex 挖出的类名（含 `clock`/`withdate` 且属于 keyguard/lockscreen/`clocks.` 命名空间、且是 View） | 固件改名后自适应 |
| 状态栏时钟（可选） | `com.android.systemui.statusbar.policy.Clock` | 顺带隐藏状态栏时钟 |

排除规则（防止误伤）：`onDraw/draw/onMeasure/measure/onLayout/layout/onTouchEvent/dispatch/...` 一律不挂。

## 2. "整体隐藏"与"逐项隐藏"的判定

- `ViewRules.wholesaleSafe(className)` 为 true 的类才允许在「整体隐藏」模式下被直接 GONE：
  名字含 `withdate`、以 `animatableclockview` 结尾、含 `lockscreenclock` / `keyguardclockview`；
  含 `statusview` / `slice` / `weather` / `notification` 的一律**不**允许（它们里面还有别的东西）。
- 其它类（例如 AOSP 的 `KeyguardStatusView`）只会走「逐项」逻辑：遍历子树，按
  `ViewRules.classify()`（文本正则 + 类名 + 资源 id）判断某个子视图是时钟/日期/星期/农历，
  再按开关隐藏或在文本上删片段。

## 3. 视图树抓取（排错核心）

`ViewRules.dump()` 输出：祖先链（由外到内）+ 目标子树（最多 12 层 / 120 行），
每行形如：

```
[1] TextView id=keyguard_date (0x7f0b0123) vis=VISIBLE kind=日期+星期 text="9月12日 星期五"
```

每行都以 `VIEWTREE` 前缀写入 logcat（tag `LegionClockHider`），所以可以用
`logcat -d -s LegionClockHider:E | grep -F VIEWTREE` 精确抓取。

触发方式：App 写 `dump_token`（毫秒时间戳）→ SystemUI 侧 `ConfigStore` 收到变更 →
`ClockHider.maybeDump()`。**若此时还没捕获到目标视图，令牌不会被消耗**，等你回到锁屏捕获后自动打印。

## 4. 日志关键字（对照日志看状态）

| 关键字 | 含义 |
|---|---|
| `引擎启动 pkg=... 框架=...` | Hook 引擎已在目标进程起来 |
| `HOOK OK <类名>（自身方法 N 个，允许整体隐藏=true/false）` | 目标类存在且挂载成功 |
| `类不存在（跳过）<类名>` | 本机没有这个类 → 看自动发现的候选 |
| `首次捕获锁屏时钟视图 <类名> → ...` | 真的抓到了锁屏时钟视图 |
| `已处理 <类名> 内 N 个视图（方式=整体隐藏/分项隐藏）` | 实际隐藏动作已执行 |
| `ZUI 已知类 AnimatableClockViewWithDate 在本机 存在 ✔ / 不存在 ✘` | 一眼看出固件是否改名 |
| `自动发现结束，候选类累计 N 个` | dex 挖掘完成 |

## 5. 如果 v1.0.0 在真机上无效，v1.0.1 的修法

1. 看 `[H]` 段（直接列 SystemUI.dex 里所有含 `Clock` 的类）拿到真实类名；
2. 把该类名填进 App「手动补充类名」即可临时生效（无需新版本）；
3. 若该类**不是 View 而是 Controller/ViewModel**（例如 AOSP 的 `ClockFaceController`
   或 ZUI 的类似物），则需要改成"挂它的方法、在回调里拿到它持有的 View/布局再隐藏" ——
   这时把 `[H]` 段与 `VIEWTREE` 段一起发回，即可据此实现。

## 6. 已知的取舍

- 周期复检 500ms 一次，只对"已捕获的视图"做几十次属性读，开销可忽略；
- 文本级删除会保留原文本用于还原（`WeakHashMap<TextView,String>`），因此"只删星期保留日期"是可逆的；
- 极端情况下若系统每帧重写文本，`GONE` 外观（默认）不受影响，`INVISIBLE`/仅删片段可能出现
  极短暂的原文本闪回（会在同一次刷新后立刻被改回）。
